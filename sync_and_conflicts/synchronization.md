# Алгоритм синхронизации

## 1. Общий подход
В системе используется гибридный подход к синхронизации:
- **Операционная трансформация (OT)** — для простых случаев (например, изменение разныхмм полей одного элемента)
- **Ручное разрешение** — для сложных конфликтов (одновременное изменение одного поля)

## 2. Базовые принципы
- **Версионирование** — каждая сущность имеет поле `version`, которое увеличивается при каждом изменении
- **Локальная очередь** — все изменения в оффлайне сохраняются в таблицу `sync_operation`
- **Идемпотентность** — повторная отправка одной операции не создаёт дубликатов

## 3. Алгоритм работы
1. Клиент в оффлайне выполняет действие, данные сохраняютс в локальную IndexDB, в таблицу sync_operation добавляется запись
2. При подключении к сети отправляет операции на сервер
3. Сервер проверяет версии, сравнивает состояние сущности в БД и новую версию, выявляет конфликты
4. Проверяет версии: если конфликта не было, то применяем изменения, если был, то применяем результат разрешения (описано в conflicts.md), обновляем версию <br>
7. Сервер рассылает изменения другим онлайн-участникам
8. Клиенты получают изменения и обновляют локальное состояние
